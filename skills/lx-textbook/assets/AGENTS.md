# Interactive textbook operating instructions

Read docs/brief.md. Ask only blocking questions. Use skills/lx-textbook/SKILL.md as the project's learning-experience workflow.

Before implementation, produce docs/knowledge-map.md, docs/learning-path.md, docs/storyboard.md and docs/quality-gates.md. Every concept needs prerequisites or foundational status; every relationship needs a type (prerequisite, causes, regulates, part-of, contrasts-with, analogy). Every scene explains why, how and what changes. Every movement has a learning purpose. Every model has assumptions, valid inputs and limits. Every lesson has prediction before reveal and transfer. Verify sources and mark uncertainty.

Write continuous explanatory prose. Embed visuals and experiments in its causal sequence. Keep content separate from models and rendering. Use an accessible, responsive reading layout and reduced motion. Begin with one complete 5–10 minute slice; extend to the requested full scope when authorized.

Run meaningful model and interaction tests; inspect desktop/mobile screenshots and revise when the environment permits. Report blocked checks honestly. At each stage report files, unresolved assumptions, failed gates and the next action. A build request does not require a second permission prompt after planning gates pass; a planning-only request must stop before code.
